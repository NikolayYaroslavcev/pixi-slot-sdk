# Pirate's Fortune на pixi-slot-sdk

**Русский** · [English](README.en.md)

Видеослот 5×4 и SDK, на котором он сделан. SDK лежит в `packages/slot-sdk` и отвечает за общее:
загрузку, раскладку по экрану, барабаны, раунд и показ выигрышей. Игра лежит в `games/octo-vault`
(игроку она показывается как Pirate's Fortune) и добавляет свои символы, математику и капитана-осьминога.
Новую игру можно создать из шаблона одной командой.

- Репозиторий: https://github.com/NikolayYaroslavcev/pixi-slot-sdk
- Играть: https://nikolayyaroslavcev.github.io/pixi-slot-sdk/

Стек: TypeScript (strict), PixiJS 8, `@pixi/sound`, Vite, Vitest, ESLint, Prettier, npm workspaces.
Нужен Node.js 24 (версия в `.nvmrc`).

## Запуск

```sh
npm install
npm run dev          # http://localhost:5173
npm run build        # сборка в games/octo-vault/dist
npm run preview      # http://localhost:4173
npm run test
npm run lint
npm run typecheck
npm run simulate     # 200 000 раундов без браузера, выводит RTP
```

Корневые скрипты запускают Pirate's Fortune. Другую игру запускают через её workspace:
`npm run dev -w games/<name>`. Push в `main` собирает игру и выкладывает её на GitHub Pages.

## Правила

- Поле 5×4, 15 линий.
- Ставка на спин: от 0.10 до 10.00. Начальный баланс 1,000.00.
- Линия платит за 3, 4 или 5 одинаковых символов подряд, начиная с левого барабана.
- Wild (красный осьминог) выпадает на барабанах 2, 3 и 4 и заменяет всё, кроме Scatter.
- Хватка: каждый осьминог перед подсчётом бросает от 2 до 4 щупалец, и схваченные клетки становятся
  Wild с множителем ×2, ×3 или ×5. Множители Wild на одной линии складываются.
- Scatter (сундук): 3, 4 или 5 штук дают 8, 10 или 12 фриспинов. Во фриспинах Wild остаются на
  месте до конца серии.
- Бонус можно купить: 10 фриспинов за 88 ставок.
- Выигрыш от 10 ставок показывается как Big Win, от 25 ставок как Mega Win.

| Символ | 3   | 4   | 5   |
| ------ | --- | --- | --- |
| Компас | 1.5 | 5   | 15  |
| Карта  | 1   | 3   | 8   |
| Якорь  | 0.8 | 2   | 6   |
| Ром    | 0.5 | 1.5 | 4   |
| A, K   | 0.3 | 0.8 | 2   |
| Q, J   | 0.2 | 0.5 | 1.5 |

Выплаты указаны в ставках. Кнопка **i** в игре показывает ту же таблицу для текущей ставки.

Спин запускается кнопкой Spin, пробелом или Enter. Во время вращения та же кнопка останавливает
барабаны, а во время показа выигрыша пропускает анимацию.

Ленты барабанов подобраны под RTP около 96%. На 3 миллионах спинов симуляция даёт 97.9%.

## Отладка

Вместо сервера работает mock (`games/octo-vault/src/mock`). Его поведение меняется параметрами в адресе:

| Параметр             | Что делает                                                   |
| -------------------- | ------------------------------------------------------------ |
| `?seed=7`            | Повторяет одни и те же раунды. Seed сессии пишется в консоль |
| `?scenario=<name>`   | Каждый спин останавливается на заданном поле                 |
| `?scenario=playlist` | Показывает основные сценарии по очереди                      |
| `?scenario=error`    | Каждый раунд падает с ошибкой, ставка возвращается           |
| `?debug=layout`      | Рисует границы и точки привязки элементов                    |

Сценарии: `nowin`, `win`, `multiwin`, `wild`, `tentacles`, `scatter`, `freespins4`, `freespins5`,
`bigwin`, `megawin`, `error`, `playlist`. Параметры можно сочетать, например
`?scenario=tentacles&seed=3`.

## Как устроено

```
games/octo-vault ─┐
templates/game  ──┼──▶  slot-sdk  ──▶  pixi.js, @pixi/sound
games/<new>     ──┘
```

Игра импортирует только `slot-sdk`, SDK не знает об играх. ESLint это проверяет.

```
packages/slot-sdk/src/
  core/       запуск игры, контекст, шина событий, Feature
  ecs/        World, компоненты, системы (без Pixi)
  flow/       автомат состояний и проигрыватель раунда (без Pixi)
  math/       контракт раунда, деньги, Rng с seed (без Pixi)
  reels/      барабаны: модель, вращение, отрисовка
  wins/       подсветка линий, Big Win
  layout/     раскладка для альбомной и портретной ориентации
  assets/     манифест, загрузка, экран загрузки
  ui/         кнопки, HUD, попап
  audio/      звук
  character/  анимированный персонаж
  anim/       tween и easing
games/octo-vault/src/
  config/     символы, выплаты, линии, ленты, тайминги
  math/       подсчёт линий, Хватка, фриспины (без Pixi)
  mock/       условный сервер
  features/   механики игры
  scene/      фон, логотип, рамка барабанов
templates/game/   минимальная игра 3×3, из неё создаются новые
```

Раунд целиком считает сервер (здесь mock) и отдаёт его списком шагов. Клиент только показывает
их по порядку:

```ts
[
  { type: 'reveal', grid },                               // остановить барабаны на этом поле
  { type: 'tentacles', grabs: [{ from, hits: [...] }] },  // шаг игры: Хватка
  { type: 'wins', wins, amount: 450 },                    // показать линии
  { type: 'totalWin', amount: 450 },                      // итог раунда
]
```

У каждого типа шага есть обработчик. Чтобы добавить механику, игра заводит новый тип шага и `Feature`, которая
регистрирует для него обработчик. SDK при этом не меняется: в нём нет ни слова о щупальцах или
фриспинах. Пример: `games/octo-vault/src/features/tentacleGrab/tentacleGrab.ts`.

Модули `ecs`, `flow` и `math` не зависят от Pixi, поэтому они тестируются в обычном Node, а
математику игры можно прогнать через `npm run simulate`.

Деньги хранятся в целых копейках (минорных единицах). Математика использует Rng с seed, а не
`Math.random()`.

## Паттерны и почему

| Паттерн                                  | Где                                         | Зачем                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------------------------- | ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Plugin** (`Feature`)                   | `core/Feature.ts`, все механики игры        | Механика подключается одной строкой в `main.ts` и получает всё нужное через `install(context)`. SDK не меняется, когда в игре появляется новая механика: на одном ядре собираются разные игры.                                                                                                                                                                                                  |
| **Dependency injection** (`GameContext`) | `core/GameContext.ts`                       | Всё, от чего зависит фича, передаётся одним явным объектом. Нет синглтонов и глобального поиска по имени, поэтому зависимости видны в коде, а в тестах их легко подменить.                                                                                                                                                                                                                      |
| **ECS** (`World`, компоненты, системы)   | `ecs/`, `reels/`                            | Барабаны — это много одинаковых сущностей (барабаны, клетки, символы), а данные и поведение у них меняются по отдельности. Механика добавляет компонент (например, `Held` для липких Wild) и систему, не трогая классы барабанов. ECS без Pixi, поэтому логика вращения тестируется в Node. ECS используется только там, где это окупается: интерфейс и попапы сделаны обычными объектами Pixi. |
| **State machine**                        | `flow/StateMachine.ts`, `flow/RoundFlow.ts` | Раунд всегда в одном из трёх состояний: `idle`, `spinning`, `presenting`. Недопустимый переход (второй спин во время вращения) бросает ошибку, а не ломает игру. Новая механика добавляет шаг, а не состояние.                                                                                                                                                                                  |
| **Command / Script** (шаги раунда)       | `math/round.ts`, `flow/RoundPlayer.ts`      | Сервер присылает раунд списком шагов, клиент проигрывает их по очереди, у каждого типа шага свой обработчик (Strategy). Клиент ничего не считает, поэтому показ не может разойтись с деньгами.                                                                                                                                                                                                  |
| **Observer** (`EventBus`)                | `core/EventBus.ts`, `core/GameEvents.ts`    | Части, которые не знают друг о друге, общаются типизированными событиями: остановку барабана слышит звук, начало спина видит персонаж.                                                                                                                                                                                                                                                          |
| **Adapter** (`ResultSource`)             | `math/round.ts`, `mock/`                    | Mock и настоящий сервер реализуют один интерфейс. Чтобы подключить бэкенд, меняют одну строку в `main.ts`.                                                                                                                                                                                                                                                                                      |
| **Presenter**                            | `ui/HudPresenter.ts`                        | Логика HUD (что показывать, когда кнопки активны) отделена от отрисовки и покрыта тестами.                                                                                                                                                                                                                                                                                                      |

Всё, что зависит от конкретной игры (символы, выплаты, ленты, тайминги, раскладка), лежит в
`config/` игры как данные. Код SDK их только читает.

## Новая игра

```sh
npm run create-game treasure-hunt
npm run dev -w games/treasure-hunt
```

Команда копирует `templates/game` в `games/treasure-hunt`. Получается рабочая игра 3×3 с
символами-заглушками. Дальше:

1. Символы задаются в `src/config/symbols.ts`, их вид в `src/assets.ts`, ленты в
   `src/config/reels.config.ts`.
2. Расположение элементов задаётся в `src/layout.ts`, отдельно для альбомной и портретной
   ориентации.
3. Результаты раундов отдаёт `src/mock/MockResultSource.ts`. Его можно заменить клиентом настоящего
   сервера.
4. Механики подключаются как `Feature` в `src/main.ts`.

Подробнее о файлах шаблона: [templates/game/README.md](templates/game/README.md).

## Ресурсы и экран

Файлы игры лежат в `public/assets/`, список файлов с алиасами в `src/assets.ts`. Если символу не
задан арт, проект не скомпилируется. Если файл не загрузился, игрок видит кнопку Retry.

Как подключить картинку или звук:

1. Положить файл в `public/assets/`, например `public/assets/scene/ship.webp`.
2. Добавить его в `src/assets.ts` в список `game`: `{ alias: 'ship', src: 'assets/scene/ship.webp' }`.
   Шрифт добавляется так же, с полем `family`.
3. Использовать по алиасу в фиче:

```ts
import { Assets, Sprite, type Texture } from 'pixi.js';
import type { Feature } from 'slot-sdk';

export function ship(): Feature {
  return {
    install(context) {
      const sprite = new Sprite(Assets.get<Texture>('ship')); // картинка
      context.layers.background.addChild(sprite);
      context.layout.addNode('ship', sprite); // место на экране задаётся в src/layout.ts
      context.events.on('spinStarted', () => {
        context.audio.play('click'); // звук
      });
    },
  };
}
```

4. Задать место узла `ship` в `src/layout.ts`, в `landscape` и в `portrait`. Без этого `addNode`
   бросит ошибку с именем узла.
5. Подключить фичу в `src/main.ts`: `features: [..., ship()]`.

Арт символа задаётся отдельно, в `symbols` того же файла: `{ src: 'assets/symbols/crown.svg' }`.
Пока арта нет, символ рисуется цветной заглушкой (`{ color, label }`).

Арт Pirate's Fortune (символы, рамка, звуки) генерируют скрипты в `games/octo-vault/scripts/`.
Источники и лицензии: [CREDITS.md](CREDITS.md).

Игра подстраивается под экран от 320 px до ультраширокого монитора и переключает раскладку при
повороте телефона. Учитываются вырез и безопасные зоны экрана.

## Layout

Раскладка описана данными в `src/layout.ts`: два варианта, `landscape` и `portrait`. У каждого
своя дизайн-область (например 1920×1080 и 1080×1920) и координаты узлов внутри неё. SDK сам
выбирает вариант по форме экрана, вписывает дизайн-область в окно и заново расставляет узлы при
изменении размера окна и повороте устройства. В коде игры пересчёта размеров нет.

```ts
export const layout: LayoutConfig<'reels' | 'logo' | HudNodeName> = {
  landscape: {
    width: 1920,
    height: 1080,
    nodes: {
      reels: { x: 960, y: 450, anchor: { x: 0.5, y: 0.5 } }, // центр барабанов в точке x, y
      logo: { x: 290, y: 245, scale: 0.5 },
      // ...
    },
  },
  portrait: { width: 1080, height: 1920, nodes: {/* те же узлы */} },
};
```

- Узел — это объект, который фича зарегистрировала через `context.layout.addNode('logo', view)`.
- `x`, `y` задают точку в дизайн-координатах, `scale` — масштаб, `anchor` — точку объекта,
  которая встанет в `x, y`.
- Тип `LayoutConfig<...>` проверяет, что оба варианта описывают одни и те же узлы: забытый узел
  не скомпилируется.
- Параметр `?debug=layout` в адресе рисует дизайн-область и точки всех узлов.
- Фон растягивается на весь экран, включая полосы вокруг дизайн-области
  (`context.layout.setBackground`). Вырез и безопасные зоны телефона учитываются.

## Тесты

452 unit-теста на логику: ECS, автомат и раунд, барабаны, layout, деньги, математику игры, mock и
`create-game`. CI запускает lint, typecheck, тесты и сборку, а потом создаёт игру из шаблона и
проверяет её так же.
